# Диагностика обрыва

Ниже описана инженерная сборка с `--ui-diagnostics`. Это не запись экрана,
камеры или звука. В обычной сборке без этого флага телефон не сохраняет
инженерные снимки сбоя.

## Что остаётся на телефоне

Рабочий поток `usb-stall-report` следит за состоянием Monitor. При потере
связи на две секунды сохраняется `last-usb-stall.json`. Полное исчезновение
USB из Windows тоже учитывается. Обычный сон ПК и намеренное отключение
USB через меню не заменяют снимок сбоя.

Файл содержит время, состояние камеры и USB, счётчики кадров и очередей,
температуру, состояние пакета Windows, последнюю ошибку драйвера, сообщения
ядра и стеки рабочих потоков. Предел — 256 КиБ. Не больше трёх сохранений
за загрузку. Используется один атомарно заменяемый файл. Постоянной записи
каждого кадра нет. Запись требует действующей CACHE persistence.

Если связь ещё отвечает, сначала снимите диагностику, затем перезапускайте
устройство. Если USB не отвечает, после входа в TWRP и монтирования CACHE:

```sh
adb -s <SERIAL> pull /cache/s7-native/last-usb-stall.json <LOCAL_FAULT_DIRECTORY>
adb -s <SERIAL> pull /cache/s7-native/last-exit-before-stop.json <LOCAL_FAULT_DIRECTORY>
```

Не удаляйте эти файлы до разбора. Они локальные и могут содержать серийник
или другие данные устройства. Не коммитьте и не публикуйте их без очистки.

## Что остаётся на Windows

Источники `S7Monitor` и `S7Camera` пишут в журнал **Application**.
Это события жизненного цикла, ошибки и сводные счётчики, не медиаданные.
Monitor записывает исходную ошибку Windows, размер USB-кадра, подтверждённые
байты, длительность и поколение соединения. Camera записывает начало,
остановку, ошибку захвата и сводку кадров за пять секунд. Журнал Windows
кольцевой: старые события могут быть вытеснены. Сохраните их после сбоя.

Сбор событий и состояния PnP не перезапускает службы и не меняет драйверы:

```powershell
./host-windows/diagnostics/Collect-Fault.ps1 `
  -OutputDirectory <NEW_LOCAL_DIRECTORY_OUTSIDE_GIT> -Minutes 30
```

`QueryErrors` показывает недоступные журналы. Пустой список событий не
доказывает отсутствие сбоя. Проверяйте совпадение времени на ПК и телефоне.

## Что пока не доказано

Короткий тест камеры вместе с Monitor прошёл. Полный долгий звонок WhatsApp
после исправления не воспроизведён. Новая запись нужна, если сбой повторится.
Исправление DWC3 защищает от установленной причины kernel panic при USB
wakeup. Это не доказательство, что все обрывы имеют ту же причину.
